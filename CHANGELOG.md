# Changelog

## 1.2.0, 25 October 2026

- For IT teams, macOS: `gird-fleet.sh --all-users`, run as root, checks every account on a Mac, each as that account through `sudo -n -u`, and saves a short result in `/var/db/blindspot/last.json` for an MDM to read: counts and names from fixed lists, never a path, file name or key, and no network request. `--json`, `--summary-to-stdout`, `--exit-zero`, `--list`, `--hash-accounts=<secret>` and `--deadline=<seconds>` shape a run; `--inventory` reads the saved result for an MDM's inventory field, and `--result-tags` wraps it for Jamf Pro. All the root work is in the new `gird-fleet.sh`; `gird-check.sh` holds none, and keeps only `--account-run`, the fixed lines one account's check sends back. Root runs both only from files root alone can change: the MDM installs them once in `/Library/Application Support/Blindspot`, with the options in one line of `gird-fleet.sh`, and its scheduled items only run it from there. Exit codes: 0 clear, 10 act, 11 review, 12 not checked, 13 failed. `docs/fleet.md` is the guide, with a page each for Jamf Pro, Iru and Microsoft Intune in `docs/mdm/`, marked untested until run on a real Mac. Linux follows; `gird-check.ps1` has no fleet mode.
- Keys in agent sessions: the plain-text keys check also reads the session transcripts of coding agents (Claude Code, including its prompt history and paste cache, Claude Desktop agent mode (on Linux too, and in its mode for Bedrock and other providers), Codex, including archived sessions and its thread history database, Gemini CLI, Qwen Code, OpenCode, Copilot CLI, Roo Code, Cline, Continue, Goose, Kiro, Amazon Q, Factory Droid, Cursor, Windsurf, Antigravity and Aider, and the prompts typed into Aider, Amazon Q, Continue, Copilot CLI, Factory Droid and Goose). A key there was read by an agent or given to it, so section 3 lists the agents and providers and says to rotate. It runs alongside the rest of the scan: ripgrep checks every session; without ripgrep, perl (or .NET in PowerShell) checks the newest first and the report says how many it checked. `--all-sessions` (`-AllSessions`) waits for all of them. A folder that can't be read makes the check "partly checked", never "no keys", and if the check can't start, the report says the sessions were not checked. "No keys in N agent session files" counts only the files read: a compressed session makes the check "partly checked", and a session file perl or .NET can't open is named as one that could not be read, never as a time cut (an unreadable Aider history is counted too). A session location that is a link is read by every engine, but never a pipe or a device. The agents' own folder variables are followed: Goose's `GOOSE_PATH_ROOT` and XDG folders, Cline's `CLINE_DIR` and `CLINE_SESSION_DATA_DIR`, Codex's `CODEX_SQLITE_HOME`, and on Linux `XDG_CONFIG_HOME` for VS Code, Cursor and Claude Desktop. Amazon Q's and Kiro CLI's own telemetry key (an `ASIA` key id in their database) is not counted. Under Git Bash, hits from a native `rg.exe` keep their agent. The details list each session location with how many of its files had keys (up to 20 rows), not each session file: a Claude Code session's path spells out the project folder and the username. Aider's history sits in its project and is named as it is. Antigravity's SQLite conversations are read; the encrypted `.pb` conversation files of Windsurf and Antigravity are counted and named as not checked. Nothing new is shared.
- Key formats: OpenAI admin keys, OpenAI project keys from before their length grew (48 characters after `sk-proj-`, with OpenAI's `T3BlbkFJ` marker), AWS temporary access key IDs and Bedrock API keys, and GitHub's server-to-server tokens. The key types and the agent session locations live in `data/keys.tsv` and `data/sessions.tsv`, each session location with its source. `tools/gen.sh` writes them into both scripts and refuses a key id that is not lowercase letters, digits and `_`, or that repeats; the tests fail if a script drifts from the data files.
- npm malware: the leaks check reads your lockfiles (npm, `npm-shrinkwrap.json`, pnpm, yarn, bun, including nested and bundled entries written without a URL), global installs (tools' own dependencies; the nvm, volta, fnm, asdf, mise, nodenv and pnpm folders; and under Git Bash the Windows places gird-check.ps1 reads: npm's, nvm-windows, fnm, Volta, mise and pnpm), npx and npm's download cache for the package versions GitHub's advisory database lists as malware: SANDWORM_MODE (February 2026), Axios (March), Bitwarden CLI (April), TanStack, Mistral AI and OpenSearch (May), Mastra (June), keyv (August) and tensorlake (October). npm's empty `0.0.1-security` placeholder for a removed package is not a hit, and neither is a pin in an overrides section that moves away from a bad version. Global installs are read in one pass: 60 npx folders of 200 packages took 26 seconds and now take about 3. A cache that can't be read in full is never called clean, and in the summary a finding to act on comes before it, as does the clean line "none of the N recent leaks or malware it checks". It also looks for what those worms leave behind: `gh-token-monitor`, the Mastra startup files, and worm files in a project's `.claude` or `.vscode` folder. `gh-token-monitor` runs a destructive command when the stolen GitHub token stops working, so finding it puts "stop it before you revoke any token" first, with the Mac and Linux commands, and every line of the report that says to rotate or revoke a key, in sections 3 and 5 as in the fix list, waits for it. The result page gets the same warning. Section 5 is now "Recent key leaks", and its npm row is "npm malware".
- Project settings that act on opening: the MCP section flags a project's `.claude/settings.json` or `settings.local.json` that runs hooks or other commands, turns on MCP servers without asking or sends API traffic to another server, and a `.vscode/tasks.json` task that runs when the folder opens. Comments are dropped only outside strings, so text in a string can't hide a task. Worktrees with the same settings share one row, named after the repo's own folder. They are listed as things to look at, and don't lower your score.
- Checks from GIRD's incident dossier (`docs/designs/dossier-checks.md`). The report's fields do not change; the result link gains `ex`, and a GlassWorm hit lowers the score like other compromised-machine findings:
  - Section 1 lists agents set to run commands without asking: Claude Code's `bypassPermissions` (as `permissions.defaultMode`, the only place Claude Code reads it, here and in a project's settings), Codex's `approval_policy = "never"` with `sandbox_mode = "danger-full-access"` or with its `:danger-full-access` permission profile (`default_permissions`), and in the user settings VS Code Copilot's `chat.tools.global.autoApprove` or VS Code's `chat.permissions.default` set to `autoApprove` or `autopilot` (`data/auto-approve.tsv`). The old `chat.tools.autoApprove`, dropped by VS Code 1.104 without migration, and a project's copy of the global setting, which VS Code reads from user settings only, are not settings in force; a project's old key is listed in section 2 as the setting the CVE-2025-53773 attack wrote. A project's `chat.permissions.default` set to `autoApprove` or `autopilot` is in force, since the setting declares no scope, and section 2 lists it as a project setting that acts on opening. A Codex profile written as an inline table does not count; Codex values in single quotes, TOML's literal strings, do.
  - Section 1 lists tools with a published security fix: Cursor below 3.1.2 (macOS), the Amazon Q language server below 1.69.0, Claude Code below 2.1.260 installed with npm, and `mcp-remote` from 0.0.5 and below 0.1.16 installed or named with a full version in an MCP config (`name@0.1` is a range npx resolves and is not reported) (`data/outdated.tsv`). A tool with several advisories gets one row: it says to update to the newest fix the installed version needs, or to a later one when that fix has a published hole of its own, and names each of its holes with its advisory. Each tool's advisories come from its own repository as well as GitHub's database and OSV: Claude Code's newest, GHSA-gfvf-j8jh-jxxw, is in neither of the other two.
  - Section 2 lists files in your projects that are links to your own `~/.ssh/authorized_keys`, however the link is written (`./`, `//`, a linked folder, or another case on a volume that ignores case). A link into a repo's own fixture is not one, and a link to the file's place counts before the file exists. An agent that edits one adds a login to the computer.
  - Section 5 looks for the editor extensions Socket's GlassWorm posts of January, March, April and October 2026 name as malicious (each post its own incident; extensions the posts call sleepers are left out), in the folders of the editors that install from Open VSX (Cursor, Windsurf and Devin Desktop's `~/.devin/extensions`, VSCodium, Kiro, and Antigravity's `~/.antigravity-ide/extensions` and `~/.antigravity/extensions`), with every `oorzc.ssh-tools` version, as Open VSX removed them all, and in every editor's folder the ones Microsoft also removed from its Marketplace and five GlassWorm-linked themes (two that ran hidden loaders, and three Microsoft removed as malware though Socket found no payload in the versions it read); `data/bad-extensions.tsv` carries a registry column, and VS Code's own folder, where an Open VSX build's id is the Marketplace's own extension, is skipped for the rest. It also carries an `os` column, as `data/bad-pypi.tsv` does: `microsoftvs.microsoftvs`, whose downloader ran only on Windows, is a malicious extension to remove on a Mac or Linux (a yellow row, its own fix and row 05), not a compromised machine. Extensions get a row of their own, "Editor extensions", never called npm malware, shown when clean too and counted among section 5's checks; a folder that can't be read is not called clean. GlassWorm's LaunchAgent, `~/Library/LaunchAgents/com.user.nodestart.plist`, counts next to one of those extensions; alone, it is a file to check. GlassWorm's advice says to check the LaunchAgents and look for the staging files Socket names; the March and April waves' says to check every editor for extensions you did not install. `@injectivelabs/sdk-ts` 1.20.21 is a version to update; moving the funds, from a clean machine, out of every wallet whose seed phrase or private key was used with it is the first fix after any act-now one, as the advisory says, and row 05 names it. An incident in `data/incidents.tsv` can carry a fix of its own in an optional advice column, and an update-level one a row 05 summary. An act-level fix that starts with "First" comes right after `gh-token-monitor`'s, which then leaves the rotating to the fixes after it, ahead of every fix that says to rotate: SANDWORM_MODE's says to remove its git hooks, whose pre-push hook sends npm tokens out on every push, and the MCP servers it adds.
- The incident checks live in data files: the hosted platforms in `data/platforms.tsv`, the files malware leaves on disk in `data/indicators.tsv`, the files worms plant in a project in `data/planted.tsv` and the bad Python packages in `data/bad-pypi.tsv`, each sourced in `data/incidents.tsv`. A new incident of an existing kind is data lines and `bash tools/gen.sh`, which accepts only the path tokens it translates and runs on Debian 12's mawk. The platform fix now reads "If you used OpenCode Console, Railway or Zeabur, rotate the keys stored there", and Railway's line follows its disclosure. Zeabur's line gives the date of its post, 19 October, and asks what Zeabur asks: replace every password and key stored there, revoking each old key at its provider first. OpenCode's line follows OpenCode's own post: only the Console users it emailed were affected, and OpenCode told them to revoke and replace their keys directly with each provider, as TechCrunch reports. A hosted platform's incident has its own level, `leak`, which never means a compromised machine.
- Python: `mistralai` 2.4.6, the PyPI release of the May 2026 Mistral AI compromise, which ran a credential stealer when imported on Linux, is an act-now hit on Linux, and its `/tmp/transformers.pyz` is looked for there. On a Mac or Windows, where its malware could not run, it is a version to update, with a fix to update it (`data/bad-pypi.tsv` gains an `os` column). `guardrails-ai` 0.10.1, published in the same wave (Wiz), is its own incident, Linux-only as well. The Mistral npm packages stay "a bad version to update": Mistral says their malware could not run. The result link gains `py`, set for an act-level Python incident other than LiteLLM. A file in the shared temp folder counts only when you own it, as the `owner` column of `data/indicators.tsv` says, and each incident's temp-folder files come with its own advice: LiteLLM's say to stop the process that holds `remote_code_loader.lock` and not to run Python or pip in that environment until `cook.pth`, `cook.py`, `sitecustomize.py` and their compiled copies are gone. uv's cache is walked once.
- The home folder scan runs on BusyBox's find (Alpine), which has no `-ilname`. A find that rejects the scan's options is reported in the header instead of the home folder reading as clean.
- A check that was not done in full (a home folder scan that failed, a folder it couldn't read or enter, agent sessions partly checked, a key, MCP config, project settings or allow-list file, part of npm's cache, a lockfile or an extension folder unreadable, or in PowerShell a file that took too long) gives the yellow "No findings in the paths checked", never "No findings in this scan". A shell profile, history file, agent config or `.env` file that can't be read, such as a root-owned `.env` a container wrote, is named in section 3, and row 03 says how many files could not be read instead of "no AI or cloud keys in plain text".
- Agent settings files are read in linear time on every awk: a cloned project's 4.8 MB `.vscode/settings.json` took a minute on macOS and now takes seconds.
- Hostile names: a TAB or a `|` in a folder name no longer splits a report row, and every path is shown with its control characters as `?`. A folder whose name holds a line break is not entered by `gird-check.sh`: the header names it, with the line break shown as `?`, and rows 02 to 05 don't read clean (`gird-check.ps1` reads such folders). Session transcripts in them are still read.
- npm lists: every npm version in Wiz's list for the May 2026 TanStack wave that a GitHub or OpenSSF advisory also names (not five from April's SAP and Intercom compromise that the list includes; and `wot-api` 0.8.5, which OpenSSF adds), the 89 `@mastra` packages GitHub lists, `keyv` 6.0.0 with the cacheable versions and `ecto` 5.0.1, and SANDWORM_MODE's 19 malicious packages. UiPath's builds are malware, as GitHub's advisory says, though Wiz found a bug in their payload; Mistral's stay versions to update, as Mistral says their malware could not run. The `@keyv` 6.0.0 builds and SANDWORM_MODE's four sleeper packages, which Socket said shipped without the install hook or were not malicious yet, are malware: GitHub's malware advisories say a machine that installed one is compromised, and the `@keyv` builds' fix says to rotate from another computer, as the advisory does. A bad version found only in a lockfile, with nothing installed beside it, keeps its row red, and the headline and the fix say to act if you installed that project.
- Planted files are each wave's own: `router_runtime.js` (TanStack), `math_init.js` (keyv), and a `setup.mjs` only beside one of them or when it matches the loader's published SHA-256 (`data/planted.tsv` gains `alone` and `sha256` columns); a lone `setup.mjs` is listed in section 2 as a file to read. A hook or task counts only when it runs a worm file, not when it names one.
- Project settings: a project that turns on `bypassPermissions` is flagged (Claude Code before 2.1.257 honoured it from any settings file), and an empty `ANTHROPIC_BASE_URL` is not. Linked settings, task and planted files are read only when the link ends at a regular file, so a link to `/dev/zero` or `/dev/tty` can't hold the scan.
- Folders the home scan can't read or enter, and lockfiles it can't read, are named in the header and the rows that depend on them, and the summary doesn't read clean over them. `flat` and `npm_hits` take time that grows with a line's length, not its square: 200,000 backslashes in a settings file and a 100 KB lockfile line read in under a second. `files_found` counts no `site-packages` folder, as TELEMETRY.md says and `gird-check.ps1` does.
- `gird-check.ps1` sends the right `files_found` again (it went out as 0 or 1, since two checks reused the scan list's name) and `-All` reaches the report as `all_folders` 1.
- The percentile line no longer says how many AI builders ran Blindspot: "Better than 72% of AI builders who ran Blindspot". The prompt at the end asks you to help spread awareness.
- `gird-check.ps1`: Blindspot for plain Windows PowerShell (5.1 and 7), with the same checks, wording, report and result link as `gird-check.sh`. It reads PowerShell's command history, has no game, and lists any file that takes too long to check as skipped.
- Windows: under Git Bash, MSYS2 or Cygwin the script now looks in the Windows places. Agents and MCP configs in your user folder, `%APPDATA%` and `%LOCALAPPDATA%` (Claude Desktop, Cursor, VS Code, Windsurf, Antigravity, Goose, Cline), PowerShell's command history, Windows Python installs, conda and the uv cache, the LiteLLM marker files in `%TEMP%`, and the Google Cloud, GitHub CLI and `_netrc` logins kept there. The report says `Windows 10` or `Windows 11`, the device ID comes from the Windows MachineGuid the same way the PowerShell version computes it, the terminal is `windows-terminal` in Windows Terminal, and ENTER opens your result in the Windows browser.
- WSL is recognised. It is scanned as Linux, the key advice says to use a secrets manager, ENTER opens the result with wslview or the Windows browser, and the end of the report says files on the Windows side were not checked.
- The game only starts when the terminal's settings can be changed, so terminals that can't (some Windows ones) get the spinner.
- Wording: the report and the result page say "AI builders" where they said "developers", "Better than" where they said "Safer than", the early-rank label is "AI builder", and a result with nothing in it reads "No findings in this scan" with a note that it is not a guarantee. What used to be called the certificate is now your "AI Exposure Check": the prompt, the result link and the image say so, and the image no longer says it was verified.
- Your place in line is never printed. If you are among the first 1,000, a line above your result says so ("You're one of the first 1,000 AI builders to run Blindspot."); after that there is none. The number goes only in the result link.
- A leftover `cook.pyc` alone is now a "possible leftover" to check, not an act-now hit. `cook.pth`, `cook.py`, the 1.107.0 install record, the marker files or a running loader still are.
- The spend-limit tip is a plain line under "What to do", no longer a numbered item, so the list matches the "things to fix" count in the header.
- MCP servers found inside plugin folders and caches (Codex's `.tmp/plugins`, Claude's `plugins` folder) are counted apart, such as "9 servers, 50 more in plugin folders", and shown as one line in the details. They no longer inflate the server count, and they are left out of the counts the script shares. A token written into one of those files is still flagged.
- Zeabur joins OpenCode and Railway in the check for this week's leaks: if the Zeabur CLI or its settings folder is on your Mac, it says to rotate the keys stored there. A leftover compiled `cook` file from the LiteLLM malware, which stays behind after `cook.py` is deleted, is reported as a possible leftover to check.
- That line is the only one that mentions the first 1,000: until 1,000 AI builders have run it, the line of totals under the banner is left out.
- A scan that finishes within about two seconds goes straight to the results. The game only appears when the scan is still running after that, instead of flashing up for a moment.
- The advice for keys in plain text names the place to keep them for your system: the macOS Keychain on a Mac, GNOME Keyring or KWallet on Linux, Windows Credential Manager under Git Bash, MSYS or Cygwin, and a secrets manager anywhere else.

## 1.1.0, 23 October 2026

- How you compare instead of a letter grade. The report opens with a line such as "Safer than 72% of 1,234 developers who ran Blindspot", taken from the reply to the report it already sends.
- The first 1,000 developers to run it see their number with the result, such as "You're developer #142 to run Blindspot."
- A short summary by default: one line per check and the first thing to fix. Press 1 to 5 for a check's details. `--full` prints everything, and so does running it into a file or a pipe. A saved report always has every detail.
- While it scans, the game or the spinner shows what it just found.
- One line of real totals under the banner, such as how many developers have run it. Until 1,000 have, it says you're one of the first 1,000 instead.
- When the results are ready, ENTER opens your Blindspot certificate. q quits.
- The certificate link also carries your number, the agents it found, how many SSH keys it found, how many shell history files hold keys, and the run's random ID, so the certificate page can write your post and show more of what you got right. If you press a share button there, the page sends that ID back with which button and what kind of result.
- The counts it shares also say which well-known MCP servers you have, from a fixed list, and how many others. Any other server name is never sent. They also say how many servers each app has and which apps keep a token in their config, where files with keys sit by kind of file, how many files hold each provider's keys, and which agents are idle. TELEMETRY.md lists every field.
- The web page moved to gird.ai/blindspot. Old gird.ai/check links redirect there.
- The banner says Blindspot, and the certificate opens at gird.ai/blindspot/card.

## 1.0.0, 22 October 2026

First public release.

- Five checks: coding agents, MCP servers, keys in plain text, keys saved in Claude Code allow lists, and signs of the October 2026 LiteLLM, OpenCode and Railway leaks.
- A grade from A to F and a list of what to fix.
- GIRD Runner, a game to play while it scans.
- A menu at the end: save the report, get a share card, or try Argus.
- Counts shared with gird.ai, listed in TELEMETRY.md. `--offline` and `DO_NOT_TRACK=1` turn them off.
