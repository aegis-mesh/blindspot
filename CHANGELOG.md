# Changelog

## Unreleased

- For IT teams, macOS: `sudo bash gird-check.sh --all-users` checks every account on a Mac, each as that account through `sudo -n -u`, and saves a short result in `/var/db/blindspot/last.json` for an MDM to read: counts and names from fixed lists, never a path, file name or key, and no network request. `--json`, `--summary-to-stdout`, `--exit-zero`, `--list`, `--hash-accounts=<secret>` and `--deadline=<seconds>` shape a run; `--inventory` reads the saved result for an MDM's inventory field. Exit codes: 0 clear, 10 act, 11 update, 12 not checked, 13 failed. `docs/fleet.md` is the guide, with a page each for Jamf Pro, Iru and Microsoft Intune in `docs/mdm/`, marked untested until run on a real Mac. Linux follows; `gird-check.ps1` has no fleet mode.
- Checks from GIRD's incident dossier (`docs/designs/dossier-checks.md`). The report's fields do not change; the result link gains `ex`, and a GlassWorm hit lowers the score like other compromised-machine findings:
  - Section 1 lists agents set to run commands without asking: Claude Code's `bypassPermissions`, Codex's `approval_policy = "never"` with `sandbox_mode = "danger-full-access"`, and VS Code Copilot's `chat.tools.autoApprove` or `chat.tools.global.autoApprove` in the user settings or a project's `.vscode/settings.json` (`data/auto-approve.tsv`).
  - Section 1 lists tools with a published security fix: Cursor below 3.0 (macOS), the Amazon Q language server below 1.69.0, Claude Code from 0.2.116 and below 1.0.24 installed with npm, and `mcp-remote` from 0.0.5 and below 0.1.16 installed or named in an MCP config (`data/outdated.tsv`).
  - Section 2 lists files in your projects that are links to `~/.ssh/authorized_keys`: an agent that edits one adds a login to the computer.
  - Section 5 looks for the GlassWorm VS Code extensions in the VS Code, Cursor, Windsurf, VSCodium and Kiro extension folders (`data/bad-extensions.tsv`), in a row of their own, "Editor extensions", never called npm malware, and lists `@injectivelabs/sdk-ts` 1.20.21 as a version to update, with a fix to move the funds out of any wallet made or imported with it. An incident in `data/incidents.tsv` can carry a fix of its own in an optional advice column.
- The incident checks live in data files: the hosted platforms in `data/platforms.tsv`, the files malware leaves on disk in `data/indicators.tsv`, the files worms plant in a project in `data/planted.tsv` and the bad Python packages in `data/bad-pypi.tsv`, each sourced in `data/incidents.tsv`. A new incident of an existing kind is data lines and `bash tools/gen.sh`. The platform fix now reads "If you used OpenCode Console, Railway or Zeabur, rotate the keys stored there".
- Python: `mistralai` 2.4.6, the PyPI release of the May 2026 Mistral AI compromise, which ran a credential stealer on Linux when imported, gets its own act-now row, and its `/tmp/transformers.pyz` is looked for. The Mistral npm packages stay "a bad version to update": Mistral says their malware could not run. The result link gains `py`, set for a Python incident other than LiteLLM.

- Keys in agent sessions: the plain-text keys check also reads the session transcripts of coding agents (Claude Code, Claude Desktop agent mode, Codex, Gemini CLI, Qwen Code, OpenCode, Copilot CLI, Roo Code, Cline, Continue, Goose, Kiro, Amazon Q, Factory, Cursor and Aider). A key there was read by an agent or given to it, so section 3 lists the agents and providers and says to rotate. It runs alongside the rest of the scan: ripgrep checks every session; without ripgrep, perl (or .NET in PowerShell) checks the newest first and the report says how many it checked. `--all-sessions` (`-AllSessions`) waits for all of them. Windsurf and Antigravity store sessions encrypted and are named as not checked. Nothing new is shared.
- The key types and the agent session locations live in `data/keys.tsv` and `data/sessions.tsv`. `tools/gen.sh` writes them into both scripts, and the tests fail if a script drifts from them.
- npm worms: the leaks check reads your lockfiles (npm, pnpm, yarn, bun), global installs, npx and npm's download cache for the package versions GitHub's advisory database lists as malware: Axios (March 2026), TanStack and Mistral AI (May), Bitwarden CLI (April), Mastra (June), keyv (August), and the fake AI tool packages such as `claud-code` (February). It also looks for what those worms leave behind: `gh-token-monitor`, the Mastra startup files, and worm files in a project's `.claude` or `.vscode` folder. `gh-token-monitor` erases your home folder when the stolen GitHub token stops working, so finding it puts "remove it before you revoke any token" first. Section 5 is now "Recent key leaks".
- Project settings that act on opening: the MCP section flags a project's `.claude/settings.json` that runs hooks, turns on MCP servers without asking or sends API traffic to another server, and a `.vscode/tasks.json` task that runs when the folder opens. They are listed as things to look at, and don't lower your score.
- npm worms: the leaks check reads your lockfiles (npm, `npm-shrinkwrap.json`, pnpm, yarn, bun), global installs (including tools' own dependencies and the nvm, volta, fnm, asdf, mise, nodenv and pnpm folders), npx and npm's download cache for the package versions GitHub's advisory database lists as malware: SANDWORM_MODE (February 2026), Axios (March), Bitwarden CLI (April), TanStack, Mistral AI and OpenSearch (May), Mastra (June), keyv (August) and tensorlake (October). A pin in an overrides section that moves away from a bad version is not a hit. It also looks for what those worms leave behind: `gh-token-monitor`, the Mastra startup files, and worm files in a project's `.claude` or `.vscode` folder. `gh-token-monitor` runs a destructive command when the stolen GitHub token stops working, so finding it puts "stop it before you revoke any token" first, with the Mac and Linux commands, and every other fix that rotates a key waits for it. The result page gets the same warning. Section 5 is now "Recent key leaks".
- Project settings that act on opening: the MCP section flags a project's `.claude/settings.json` or `settings.local.json` that runs hooks or other commands, turns on MCP servers without asking or sends API traffic to another server, and a `.vscode/tasks.json` task that runs when the folder opens. Worktrees with the same settings share one row. They are listed as things to look at, and don't lower your score.
- The percentile line no longer says how many AI builders ran Blindspot: "Better than 72% of AI builders who ran Blindspot". The prompt at the end asks you to help spread awareness.
- `gird-check.ps1`: Blindspot for plain Windows PowerShell (5.1 and 7), with the same checks, wording, report and result link as `gird-check.sh`. It reads PowerShell's command history, has no game, and lists any file that takes too long to check as skipped.
- Windows: under Git Bash, MSYS2 or Cygwin the script now looks in the Windows places. Agents and MCP configs in your user folder, `%APPDATA%` and `%LOCALAPPDATA%` (Claude Desktop, Cursor, VS Code, Windsurf, Antigravity, Goose, Cline), PowerShell's command history, Windows Python installs, conda and the uv cache, the LiteLLM marker files in `%TEMP%`, and the Google Cloud, GitHub CLI and `_netrc` logins kept there. The report says `Windows 10` or `Windows 11`, the device ID comes from the Windows MachineGuid the same way the PowerShell version computes it, the terminal is `windows-terminal` in Windows Terminal, and ENTER opens your result in the Windows browser.
- WSL is recognised. It is scanned as Linux, the key advice says to use a secrets manager, ENTER opens the result with wslview or the Windows browser, and the end of the report says files on the Windows side were not checked.
- The game only starts when the terminal's settings can be changed, so terminals that can't (some Windows ones) get the spinner.
- Wording: the report and the result page say "AI builders" where they said "developers", "Better than" where they said "Safer than", the early-rank label is "AI builder", and a result with nothing in it reads "No findings in this scan" with a note that it is not a guarantee. What used to be called the certificate is now your "AI Exposure Check": the prompt, the result link and the image say so, and the image no longer says it was verified.
- Every device gets its number, not only the first 1,000: "You're AI builder #1,234 to run Blindspot." Up to 1,000 it adds "One of the first 1,000."
- A leftover `cook.pyc` alone is now a "possible leftover" to check, not an act-now hit. `cook.pth`, `cook.py`, the 1.107.0 install record, the marker files or a running loader still are.
- The spend-limit tip is a plain line under "What to do", no longer a numbered item, so the list matches the "things to fix" count in the header.
- MCP servers found inside plugin folders and caches (Codex's `.tmp/plugins`, Claude's `plugins` folder) are counted apart, such as "9 servers, 50 more in plugin folders", and shown as one line in the details. They no longer inflate the server count, and they are left out of the counts the script shares. A token written into one of those files is still flagged.
- Zeabur joins OpenCode and Railway in the check for this week's leaks: if the Zeabur CLI or its settings folder is on your Mac, it says to rotate the keys stored there. A leftover compiled `cook` file from the LiteLLM malware, which stays behind after `cook.py` is deleted, is reported as a possible leftover to check.
- Your number among the first 1,000 now sits on its own line above your result, not inside it, and is the only line that mentions the first 1,000. Until 1,000 developers have run it, the line under the banner is left out.
- A scan that finishes within about two seconds goes straight to the results. The game only appears when the scan is still running after that, instead of flashing up for a moment.
- The advice for keys in plain text names the place to keep them for your system: the macOS Keychain on a Mac, GNOME Keyring or KWallet on Linux, Windows Credential Manager under Git Bash, MSYS or Cygwin, and a secrets manager anywhere else.

## 1.1.0, 23 October 2026

- How you compare instead of a letter grade. The report opens with a line such as "Safer than 72% of 1,234 developers who ran Blindspot", taken from the reply to the report it already sends.
- The first 1,000 developers to run it see their number with the result, such as "You're developer #142 to run Blindspot."
- A short summary by default: one line per check and the first thing to fix. Press 1 to 5 for a check's details. `--full` prints everything, and so does running it into a file or a pipe. A saved report always has every detail.
- While it scans, the game or the spinner shows what it just found.
- One line of real totals under the banner, such as how many developers have run it. Until 1,000 have, it says you're one of the first 1,000 instead.
- When the results are ready, ENTER opens your Blindspot certificate. q quits.
- The certificate link also carries your number, the agents it found, how many SSH keys it found, how many shell history files hold keys, and the run's random ID, so the certificate page can write your post and show more of what you got right. If you press a share button there, the page sends that ID back with which button and what kind of result.
- The counts it shares also say which well-known MCP servers you have, from a fixed list, and how many others. Any other server name is never sent. They also say how many servers each app has and which apps keep a token in their config, where files with keys sit by kind of file, how many files hold each provider's keys, and which agents are idle. TELEMETRY.md lists every field.
- The web page moved to gird.ai/blindspot. Old gird.ai/check links redirect there.
- The banner says Blindspot, and the certificate opens at gird.ai/blindspot/card.

## 1.0.0, 22 October 2026

First public release.

- Five checks: coding agents, MCP servers, keys in plain text, keys saved in Claude Code allow lists, and signs of the October 2026 LiteLLM, OpenCode and Railway leaks.
- A grade from A to F and a list of what to fix.
- GIRD Runner, a game to play while it scans.
- A menu at the end: save the report, get a share card, or try Argus.
- Counts shared with gird.ai, listed in TELEMETRY.md. `--offline` and `DO_NOT_TRACK=1` turn them off.
