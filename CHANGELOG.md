# Changelog

## Unreleased

- Keys in agent sessions: the plain-text keys check also reads the session transcripts of coding agents (Claude Code, including its prompt history and paste cache, Claude Desktop agent mode, Codex, including archived sessions, Gemini CLI, Qwen Code, OpenCode, Copilot CLI, Roo Code, Cline, Continue, Goose, Kiro, Amazon Q, Factory, Cursor, Windsurf, Antigravity and Aider). A key there was read by an agent or given to it, so section 3 lists the agents and providers and says to rotate. It runs alongside the rest of the scan: ripgrep checks every session; without ripgrep, perl (or .NET in PowerShell) checks the newest first and the report says how many it checked. `--all-sessions` (`-AllSessions`) waits for all of them. A folder that can't be read makes the check "partly checked", never "no keys", and if the check can't start, the report says the sessions were not checked. The details name the session folders, never a session file whose path spells out a project and a username. Session stores kept encrypted (some of Windsurf's and Antigravity's) are named as not checked. Nothing new is shared.
- Key formats: OpenAI admin keys, AWS temporary access key IDs and Bedrock API keys, and GitHub's server-to-server tokens. The key types and the agent session locations live in `data/keys.tsv` and `data/sessions.tsv`, each session location with its source. `tools/gen.sh` writes them into both scripts and refuses a key id that is not lowercase letters, digits and `_`, or that repeats; the tests fail if a script drifts from the data files.
- npm malware: the leaks check reads your lockfiles (npm, `npm-shrinkwrap.json`, pnpm, yarn, bun, including nested and bundled entries written without a URL), global installs (tools' own dependencies; the nvm, volta, fnm, asdf, mise, nodenv and pnpm folders; and under Git Bash the Windows places gird-check.ps1 reads: npm's, nvm-windows, fnm, Volta, mise and pnpm), npx and npm's download cache for the package versions GitHub's advisory database lists as malware: SANDWORM_MODE (February 2026), Axios (March), Bitwarden CLI (April), TanStack, Mistral AI and OpenSearch (May), Mastra (June), keyv (August) and tensorlake (October). npm's empty `0.0.1-security` placeholder for a removed package is not a hit, and neither is a pin in an overrides section that moves away from a bad version. A cache that can't be read in full is never called clean, and in the summary a finding to act on comes before it. It also looks for what those worms leave behind: `gh-token-monitor`, the Mastra startup files, and worm files in a project's `.claude` or `.vscode` folder. `gh-token-monitor` runs a destructive command when the stolen GitHub token stops working, so finding it puts "stop it before you revoke any token" first, with the Mac and Linux commands, and every other fix that rotates a key waits for it. The result page gets the same warning. Section 5 is now "Recent key leaks", and its npm row is "npm malware".
- Project settings that act on opening: the MCP section flags a project's `.claude/settings.json` or `settings.local.json` that runs hooks or other commands, turns on MCP servers without asking or sends API traffic to another server, and a `.vscode/tasks.json` task that runs when the folder opens. Comments are dropped only outside strings, so text in a string can't hide a task. Worktrees with the same settings share one row, named after the repo's own folder. They are listed as things to look at, and don't lower your score.
- Checks from GIRD's incident dossier (`docs/designs/dossier-checks.md`). The report's fields do not change; the result link gains `ex`, and a GlassWorm hit lowers the score like other compromised-machine findings:
  - Section 1 lists agents set to run commands without asking: Claude Code's `bypassPermissions`, Codex's `approval_policy = "never"` with `sandbox_mode = "danger-full-access"`, and VS Code Copilot's `chat.tools.global.autoApprove` in the user settings (`data/auto-approve.tsv`). The old `chat.tools.autoApprove`, dropped by VS Code 1.104 without migration, and a project's copy of the global setting, which VS Code reads from user settings only, are not settings in force; a project's old key is listed in section 2 as the setting the CVE-2025-53773 attack wrote. A Codex profile written as an inline table does not count.
  - Section 1 lists tools with a published security fix: Cursor below 3.0 (macOS), the Amazon Q language server below 1.69.0, Claude Code from 0.2.116 and below 1.0.24 installed with npm, and `mcp-remote` from 0.0.5 and below 0.1.16 installed or named with a full version in an MCP config (`name@0.1` is a range npx resolves and is not reported) (`data/outdated.tsv`).
  - Section 2 lists files in your projects that are links to your own `~/.ssh/authorized_keys` (a link into a repo's own fixture is not one; a link to the file's place counts before the file exists): an agent that edits one adds a login to the computer.
  - Section 5 looks for the GlassWorm extensions in the folders of the editors that install from Open VSX (Cursor, Windsurf, VSCodium and Kiro), where the malicious builds were published; `data/bad-extensions.tsv` carries a registry column, and VS Code's own folder, whose Marketplace builds of the same versions are clean, is skipped for them. GlassWorm's LaunchAgent, `~/Library/LaunchAgents/com.user.nodestart.plist`, is listed with the extensions, the fix names what section 5 lists, and the incident's advice names the staging files to remove. Extensions get a row of their own, "Editor extensions", never called npm malware. `@injectivelabs/sdk-ts` 1.20.21 is a version to update, with a fix to move the funds out of any wallet made or imported with it, shown before the update. An incident in `data/incidents.tsv` can carry a fix of its own in an optional advice column.
- The incident checks live in data files: the hosted platforms in `data/platforms.tsv`, the files malware leaves on disk in `data/indicators.tsv`, the files worms plant in a project in `data/planted.tsv` and the bad Python packages in `data/bad-pypi.tsv`, each sourced in `data/incidents.tsv`. A new incident of an existing kind is data lines and `bash tools/gen.sh`, which accepts only the path tokens it translates and runs on Debian 12's mawk. The platform fix now reads "If you used OpenCode Console, Railway or Zeabur, rotate the keys stored there", and Railway's line follows its disclosure.
- Python: `mistralai` 2.4.6, the PyPI release of the May 2026 Mistral AI compromise, which ran a credential stealer when imported on Linux, is an act-now hit on Linux, and its `/tmp/transformers.pyz` is looked for there. On a Mac or Windows, where its malware could not run, it is a version to update, with a fix to update it (`data/bad-pypi.tsv` gains an `os` column). The Mistral npm packages stay "a bad version to update": Mistral says their malware could not run. The result link gains `py`, set for an act-level Python incident other than LiteLLM. A file in the shared temp folder counts only when you own it, as the `owner` column of `data/indicators.tsv` says, and each incident's temp-folder files come with its own advice: LiteLLM's say to stop the process that holds `remote_code_loader.lock` and not to run Python or pip in that environment until its cook files are gone. uv's cache is walked once.
- The home folder scan runs on BusyBox's find (Alpine), which has no `-lname`. A find that rejects the scan's options is reported in the header instead of the home folder reading as clean.
- Hostile names: a TAB, a newline or a `|` in a folder name no longer splits a report row. Every path is shown with its control characters as `?`, and keeps its row's text.
- `gird-check.ps1` sends the right `files_found` again (it went out as 0 or 1, since two checks reused the scan list's name) and `-All` reaches the report as `all_folders` 1.
- The percentile line no longer says how many AI builders ran Blindspot: "Better than 72% of AI builders who ran Blindspot". The prompt at the end asks you to help spread awareness.
- `gird-check.ps1`: Blindspot for plain Windows PowerShell (5.1 and 7), with the same checks, wording, report and result link as `gird-check.sh`. It reads PowerShell's command history, has no game, and lists any file that takes too long to check as skipped.
- Windows: under Git Bash, MSYS2 or Cygwin the script now looks in the Windows places. Agents and MCP configs in your user folder, `%APPDATA%` and `%LOCALAPPDATA%` (Claude Desktop, Cursor, VS Code, Windsurf, Antigravity, Goose, Cline), PowerShell's command history, Windows Python installs, conda and the uv cache, the LiteLLM marker files in `%TEMP%`, and the Google Cloud, GitHub CLI and `_netrc` logins kept there. The report says `Windows 10` or `Windows 11`, the device ID comes from the Windows MachineGuid the same way the PowerShell version computes it, the terminal is `windows-terminal` in Windows Terminal, and ENTER opens your result in the Windows browser.
- WSL is recognised. It is scanned as Linux, the key advice says to use a secrets manager, ENTER opens the result with wslview or the Windows browser, and the end of the report says files on the Windows side were not checked.
- The game only starts when the terminal's settings can be changed, so terminals that can't (some Windows ones) get the spinner.
- Wording: the report and the result page say "AI builders" where they said "developers", "Better than" where they said "Safer than", the early-rank label is "AI builder", and a result with nothing in it reads "No findings in this scan" with a note that it is not a guarantee. What used to be called the certificate is now your "AI Exposure Check": the prompt, the result link and the image say so, and the image no longer says it was verified.
- Every device gets its number, not only the first 1,000: "You're AI builder #1,234 to run Blindspot." Up to 1,000 it adds "One of the first 1,000."
- A leftover `cook.pyc` alone is now a "possible leftover" to check, not an act-now hit. `cook.pth`, `cook.py`, the 1.107.0 install record, the marker files or a running loader still are.
- The spend-limit tip is a plain line under "What to do", no longer a numbered item, so the list matches the "things to fix" count in the header.
- MCP servers found inside plugin folders and caches (Codex's `.tmp/plugins`, Claude's `plugins` folder) are counted apart, such as "9 servers, 50 more in plugin folders", and shown as one line in the details. They no longer inflate the server count, and they are left out of the counts the script shares. A token written into one of those files is still flagged.
- Zeabur joins OpenCode and Railway in the check for this week's leaks: if the Zeabur CLI or its settings folder is on your Mac, it says to rotate the keys stored there. A leftover compiled `cook` file from the LiteLLM malware, which stays behind after `cook.py` is deleted, is reported as a possible leftover to check.
- Your number among the first 1,000 now sits on its own line above your result, not inside it, and is the only line that mentions the first 1,000. Until 1,000 developers have run it, the line under the banner is left out.
- A scan that finishes within about two seconds goes straight to the results. The game only appears when the scan is still running after that, instead of flashing up for a moment.
- The advice for keys in plain text names the place to keep them for your system: the macOS Keychain on a Mac, GNOME Keyring or KWallet on Linux, Windows Credential Manager under Git Bash, MSYS or Cygwin, and a secrets manager anywhere else.

## 1.1.0, 23 October 2026

- How you compare instead of a letter grade. The report opens with a line such as "Safer than 72% of 1,234 developers who ran Blindspot", taken from the reply to the report it already sends.
- The first 1,000 developers to run it see their number with the result, such as "You're developer #142 to run Blindspot."
- A short summary by default: one line per check and the first thing to fix. Press 1 to 5 for a check's details. `--full` prints everything, and so does running it into a file or a pipe. A saved report always has every detail.
- While it scans, the game or the spinner shows what it just found.
- One line of real totals under the banner, such as how many developers have run it. Until 1,000 have, it says you're one of the first 1,000 instead.
- When the results are ready, ENTER opens your Blindspot certificate. q quits.
- The certificate link also carries your number, the agents it found, how many SSH keys it found, how many shell history files hold keys, and the run's random ID, so the certificate page can write your post and show more of what you got right. If you press a share button there, the page sends that ID back with which button and what kind of result.
- The counts it shares also say which well-known MCP servers you have, from a fixed list, and how many others. Any other server name is never sent. They also say how many servers each app has and which apps keep a token in their config, where files with keys sit by kind of file, how many files hold each provider's keys, and which agents are idle. TELEMETRY.md lists every field.
- The web page moved to gird.ai/blindspot. Old gird.ai/check links redirect there.
- The banner says Blindspot, and the certificate opens at gird.ai/blindspot/card.

## 1.0.0, 22 October 2026

First public release.

- Five checks: coding agents, MCP servers, keys in plain text, keys saved in Claude Code allow lists, and signs of the October 2026 LiteLLM, OpenCode and Railway leaks.
- A grade from A to F and a list of what to fix.
- GIRD Runner, a game to play while it scans.
- A menu at the end: save the report, get a share card, or try Argus.
- Counts shared with gird.ai, listed in TELEMETRY.md. `--offline` and `DO_NOT_TRACK=1` turn them off.
