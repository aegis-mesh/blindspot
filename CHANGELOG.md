# Changelog

## 1.2.0, 25 October 2026

- For IT teams, macOS: `gird-fleet.sh --all-users`, run as root, checks every account on a Mac, each as that account through `sudo -n -u`, and saves a short result in `/var/db/blindspot/last.json` for an MDM to read: counts and names from fixed lists, never a path, file name or key, and no network request. `--json`, `--summary-to-stdout`, `--exit-zero`, `--list`, `--hash-accounts=<secret>` and `--deadline=<seconds>` shape a run; `--inventory` reads the saved result for an MDM's inventory field, and `--result-tags` wraps it for Jamf Pro. All the root work is in the new `gird-fleet.sh`; `gird-check.sh` holds none, and keeps only `--account-run`, the fixed lines one account's check sends back. Root runs both only from files root alone can change: the MDM installs them once in `/Library/Application Support/Blindspot`, with the options in one line of `gird-fleet.sh`, and its scheduled items only run it from there. Exit codes: 0 clear, 10 act, 11 review, 12 not checked, 13 failed. `docs/fleet.md` is the guide, with a page each for Jamf Pro, Iru and Microsoft Intune in `docs/mdm/`, marked untested until run on a real Mac. Root's own check of the Mac is timed, so an account that fills `/tmp` with names like the malware's markers can't hold up the run, and one that runs out of time leaves the Mac partly checked. A platform found on an account reads as its own summary ("OpenCode found: got its breach email? Rotate keys"), never as one the account uses. A file named like a malware's marker in `/tmp` is only a possible sign, for the Mac or for the account that owns it, since any account can hard-link a file it can reach under such a name; a running LiteLLM loader counts only when root's own process holds its lock. An account whose shell profile moves an agent's folders reads partly checked, and each account run is told its time, so a slow session check no longer hides what it found. Linux follows; `gird-check.ps1` has no fleet mode.
- Keys in agent sessions: the plain-text keys check also reads the session transcripts of coding agents (Claude Code, including its prompt history and paste cache, Claude Desktop agent mode (on Linux too, and in its mode for Bedrock and other providers), Codex, including archived sessions and its thread history database, Gemini CLI, Qwen Code, OpenCode, Copilot CLI, Roo Code, Cline, Continue, Goose, Kiro, Amazon Q, Factory Droid, Cursor, Windsurf, Antigravity and Aider, and the prompts typed into Aider, Amazon Q, Continue, Copilot CLI, Factory Droid and Goose). A key there was read by an agent or given to it, so section 3 lists the agents and providers and says to rotate. It runs alongside the rest of the scan: ripgrep checks every session; without ripgrep, perl (or .NET in PowerShell) checks the newest first and the report says how many it checked. `--all-sessions` (`-AllSessions`) waits for all of them. A folder that can't be read makes the check "partly checked", never "no keys", and if the check can't start, the report says the sessions were not checked. "No keys in N agent session files" counts only the files read: a compressed session makes the check "partly checked", and a session file perl or .NET can't open, empty or not, is named as one that could not be read, never as a time cut (an unreadable Aider history is counted too, and in PowerShell one that took too long to check). A session location that is a link is read by every engine, but never a pipe or a device, and no engine follows a link inside a session folder. A key right after a carriage return is found by every engine. The agents' own folder variables are followed, written with a trailing or doubled slash too: Goose's `GOOSE_PATH_ROOT` and XDG folders, Cline's `CLINE_DIR` and `CLINE_SESSION_DATA_DIR`, Codex's `CODEX_SQLITE_HOME`, and on Linux `XDG_CONFIG_HOME` for VS Code, Cursor and Claude Desktop. Amazon Q's and Kiro CLI's own telemetry key (an `ASIA` key id in their database) is not counted. Under Git Bash, hits from a native `rg.exe` keep their agent. The details list each session location with how many of its files had keys (up to 20 rows), not each session file: a Claude Code session's path spells out the project folder and the username. Aider's history sits in its project and is named as it is. Antigravity's SQLite conversations are read; the encrypted `.pb` conversation files of Windsurf and Antigravity are counted and named as not checked. Nothing new is shared.
- Key formats: OpenAI admin keys, OpenAI project keys from before their length grew (48 characters after `sk-proj-`, with OpenAI's `T3BlbkFJ` marker), OpenAI user keys made outside a project (`sk-None-`, in both lengths), AWS temporary access key IDs and Bedrock API keys, and GitHub's server-to-server tokens. The key types and the agent session locations live in `data/keys.tsv` and `data/sessions.tsv`, each session location with its source. `tools/gen.sh` writes them into both scripts and refuses a key id that is not lowercase letters, digits and `_`, or that repeats; the tests fail if a script drifts from the data files. A Bedrock short-term key counts only with key characters after its fixed start and the 104 characters every such key shares, so text about keys, such as Blindspot's own scripts read by an agent, is not one, and an `AIza` or `r8_` inside base64, such as an image pasted into an agent, is not a Google or Replicate key. GitHub's server-to-server tokens are matched by their two shapes, ghs_ and 36 letters and digits or GitHub's stateless ghs_ JWT of about 520 characters, never inside a word such as `highs_`. A key right after an escape such as `\n` counts in every file the keys check reads, as it does in sessions. The keys check also reads the files where Cline 4.x keeps API keys in plain text, `~/.cline/data/secrets.json` and `settings/providers.json` beside it (or under `CLINE_DATA_DIR` or `CLINE_DIR`, and the file `CLINE_PROVIDER_SETTINGS_PATH` names).

- Project settings that act on opening: the MCP section flags a project's `.claude/settings.json` or `settings.local.json` that runs hooks or other commands (`statusLine`, `fileSuggestion`, `subagentStatusLine` and the credential helpers; a hook event with an empty list, and hooks or a status line that the project's `disableAllHooks` turns off, run nothing and are not counted), turns on MCP servers without asking or sends API traffic to another server, and a `.vscode/tasks.json` task that runs when the folder opens.
